# Quantifying the Efficiency-Fidelity Trade-off in Contextual RAG

MSc thesis artifact. `RAG.ipynb` is the single submitted artifact: pipeline,
execution, statistics, and figures all live in it. This README explains how
to reproduce it.

## Layout

| Path | Contents |
|---|---|
| `RAG.ipynb` | Full pipeline (sections 1-13) and analysis (sections 14-31 + appendix). Run top to bottom. |
| `results/` | Raw experimental output. `results.csv` (222 rows: 144 core + 48 chunk-size + 24 late-chunking + 6 reranking), `results_with_composite.csv`, `cost_ledger.csv` (every API call, provider-billed cost). Never regenerate by hand - these are read, not derived, by the analysis. |
| `thesis_tables/` | One CSV per printed table in sections 14-28, named by thesis section (e.g. `5_6_anova_ragas_faithfulness.csv`). Regenerated by running the notebook. |
| `figures/` | The eight thesis figures (PDF + PNG), regenerated by section 30. |
| `cache/` | Per-stage resumability caches (`snippets_*.jsonl`, `answers.jsonl`, `judgments.jsonl`, `eval_metrics.jsonl`, `emb_*.npy`). Not committed; the pipeline is designed to skip any (corpus, chunking, size, format, generator) combination already present, so a top-to-bottom re-run makes no new API calls when these caches are complete. |
| `thesis_numbers.txt` | Full console log of sections 14-28, written by the notebook itself as it runs. |

## Reproducing

1. Create the environment (see Environment below) and set `OPENAI_API_KEY`
   and `ANTHROPIC_API_KEY`.
2. Open `RAG.ipynb` and run all cells top to bottom. No manual edits
   required.
   - Sections 1-13 (pipeline) are fully resumable: with `results/`, `cache/`,
     and `results/analysis/` populated from the original run, every stage
     checks its own cache/results file first and skips anything already
     done, so a full re-run makes zero new API calls.
   - Sections 14-28 (analysis) read only from `results/*.csv` and
     `cache/*.jsonl` - no API calls at all, ever.
   - Section 30 (Figures) reads the same on-disk data.
3. `thesis_tables/*.csv`, `figures/*`, and `thesis_numbers.txt` are
   regenerated in place.

The appendix (six-term ANOVA on the legacy `faithfulness` column, and the
per-metric battery built on it) is preserved for the record - see the
appendix markdown cell in the notebook for why it was superseded by sections
14-28. Its output is redirected to `results/analysis/superseded/` so a
re-run cannot recreate `results/analysis/anova_faithfulness.csv` at the
original path now occupied by
`results/analysis/SUPERSEDED_anova_faithfulness_sixterm_legacyDV.csv`.

indefinitely in network-restricted environments.

## TOON serialization

The TOON serializer (`RAG.ipynb`, section 3) is a from-scratch Python
implementation of the tabular array form defined in:

> J. Schopplich, "TOON Specification, Version 3.0," Working Draft, 24 Nov
> 2025. https://github.com/toon-format/spec/blob/main/SPEC.md. Accessed
> July 2026.

v3.0 was the current published version throughout the implementation period
(first commit 18 July 2026, eight months after the spec was published).

Conforming clauses implemented: header syntax (6), tabular arrays (9.3),
delimiter scoping (11), indentation (12), field ordering (9.3).

Two documented deviations from the spec:
- String escaping uses RFC 4180 doubled-quote escaping rather than the
  backslash escaping required by clause 7.1.
- Values containing colons, brackets, or reserved literals are not quoted
  as required by clause 7.2.

Measured impact of both deviations, over the full corpus: 174 of 51,980
field values (0.33%), 348 characters total. Strict conformance would
increase TOON's output size, so the token-saving figures reported in the
thesis are conservative relative to a fully spec-conformant serializer.
Validated by the round-trip self-test in section 3a (lossless round-trip on
values containing embedded commas, quotes, and newlines).
