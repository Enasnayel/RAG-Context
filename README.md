# Quantifying the Efficiency-Fidelity Trade-off in Contextual RAG

MSc thesis artifact. `RAG.ipynb` is the single submitted artifact: pipeline,
execution, statistics, and figures all live in it. This README explains what
can be reproduced from this repository and what cannot.

## What runs from this repository

**Read this first.** The repository contains the experimental results but not
the inputs that produced them.

| Sections | Runs from a fresh clone? | Requires |
| -------- | ------------------------ | -------- |
| 14 onwards (analysis) | **Yes** | `results/*.csv` only. No corpora, no API keys, no cache. |
| 1-10 (component definitions) | Yes, with dependencies installed | API keys for the client constructors in section 1 |
| 11 (Execute) | **No — and should not be run** | Corpora and caches that are not in this repository |

The corpora (`data/`) and the resumability caches (`cache/`) are excluded from
version control. The original copies were lost in a hardware failure during
the writing period, so they cannot be supplied. HotpotQA, MS MARCO, and
FinanceBench can be re-downloaded from HuggingFace; the Bahrain Polytechnic
policy corpus is institutional data held under ethics approval
AREC/ETH/2026/017 and is not redistributable.

The consequence for reproduction: **the analysis is fully reproducible from
this repository, the pipeline is not.** Every number, table, and figure in
Chapter 5 of the thesis is derived from `results/results.csv`, which is
committed here.

One analysis section is affected by the cache loss. Section 25 (5.11,
cross-judge bias) originally read `cache/judgments.jsonl` and
`cache/answers.jsonl`; it now reads the tables produced by the original run
(`thesis_tables/5_11_*.csv`). The reported figures are unchanged.

## Notebook structure

Sections 1-13 define the pipeline components and the factorial driver.
Nothing executes against data until section 11 calls `run_factorial()`.
Cell ordering is therefore not pipeline ordering: within `run_factorial()`,
the order is chunk, contextualize, serialize, embed, index, retrieve,
generate, judge.

Sections 14-31 are the analysis, reading `results/*.csv` only:

| Section | Contents |
| ------- | -------- |
| 14 | Analysis setup: shared helpers, metric definitions, assertion that the core factorial is 144 rows |
| 15, 15b | Experimental scope; corpus statistics |
| 16 | 5.2 Assumption checks (Shapiro-Wilk, Levene, eight DVs) |
| 17, 17b | 5.3 Token efficiency by stage |
| 18-19 | 5.4 Retrieval quality; 5.5 Generation fidelity |
| 20a-20f | 5.6 ANOVA and hypothesis tests, split into six cells: pre-registered two-way model, conflict resolution, three-way extension, logit extension, per-corpus refit, robustness checks (Holm, Friedman, simple effects) |
| 21-23 | 5.7 Chunk-size sensitivity; 5.8 Late chunking; 5.9 Reranking ablation |

| 30-31 | Figures; commit stamp |

Sections 12 and 29 do not exist. Section 29 (bootstrap variance estimation)
was removed: it requires per-question scores from `cache/`, which were lost,
and the inference it would have provided is already given by the Wilcoxon
contrasts and Cohen's dz effect sizes in section 20f.

Every section header states what the cell consumes, what it writes, and
whether it makes API calls.

## Reproducing the analysis

1. Create the environment (see Environment below).
2. Open `RAG.ipynb`. Run section 1 (Configuration), then section 14
   (Analysis setup), then sections 15 onwards.
3. `thesis_tables/*.csv`, `results/analysis/*.csv`, `figures/*`, and
   `thesis_numbers.txt` are regenerated in place.

Section 1 asserts that `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` are set,
because it constructs the provider clients. The analysis sections make no
API calls, so any non-empty values satisfy the assertion. `OFFLINE = True`
in section 1 blocks every provider call at the retry wrapper regardless.

**Do not run section 11.** It calls `run_factorial()`, which re-executes the
full experiment. With `cache/` absent it would re-contextualize every chunk
in every corpus from scratch.

## Superseded analysis

The appendix (six-term ANOVA on the legacy `faithfulness` column, and the
per-metric battery built on it) is preserved for the record — see the
appendix markdown cell in the notebook for why it was superseded. Its output
is redirected to `results/analysis/superseded/` so a re-run cannot recreate
`results/analysis/anova_faithfulness.csv` at the original path.

Section 20b (Conflict resolution) reproduces the superseded result from the
corrected code and decomposes it: the format term's sum of squares is
identical across model specifications, so the significant result arose from
residual shrinkage rather than from any change in format's effect. Both the
wrong dependent variable and the over-specified model were required; neither
alone reproduces it.

## TOON serialization

The TOON serializer (`RAG.ipynb`, section 3) is a from-scratch Python
implementation of the tabular array form defined in:

> J. Schopplich, "TOON Specification, Version 3.0," Working Draft, 24 Nov
> 2025. <https://github.com/toon-format/spec/blob/main/SPEC.md>. Accessed
> July 2026.

v3.0 was the current published version throughout the implementation period
(first commit 18 July 2026, eight months after the spec was published). No
stable Python implementation was available: the reference SDK is TypeScript,
and the community Python port was in beta and not yet spec-compliant.

Conforming clauses implemented: header syntax (6), tabular arrays (9.3),
delimiter scoping (11), indentation (12), field ordering (9.3).

Two documented deviations from the spec:

- String escaping uses RFC 4180 doubled-quote escaping rather than the
  backslash escaping required by clause 7.1.
- Values containing colons, brackets, or reserved literals are not quoted
  as required by clause 7.2.

Measured impact of both deviations, over the full corpus: 174 of 51,980
field values (0.33%), 348 characters total. Strict conformance would
increase TOON's output size, so the token-saving figures reported in the
thesis are conservative relative to a fully spec-conformant serializer.
Validated by the round-trip self-test in section 3a (lossless round-trip on
values containing embedded commas, quotes, and newlines).

## Corpora

| Corpus | Documents | Questions | Source |
| ------ | --------- | --------- | ------ |
| HotpotQA (distractor) | 498 | 50 | HuggingFace |
| MS MARCO | 500 | 50 | HuggingFace |
| FinanceBench | 41 | 50 | HuggingFace |
| Bahrain Polytechnic policy | 36 | 50 | Institutional, not redistributable |

The HotpotQA corpus pools all ten context paragraphs shipped with each
question, gold and distractor alike. Indexing only the gold documents
produced Recall@5 = MRR = 1.0, a ceiling effect leaving no headroom for
formats to differ.

The Bahrain Polytechnic question set has no published ground truth and was
generated by Claude Sonnet 5 on 30 July 2026, in a session separate from the
experimental pipeline and using a different model from the generator and
judge. It was validated post-hoc on 11 August 2026: 48 of 50 questions fully
supported, one partially supported, one containing a factual error. The set
was left unmodified because the factorial had already run against it.
