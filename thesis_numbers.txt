------------------------------------------------------------------------------
Sign convention of token_saving_vs_baseline_pct (worked example)
------------------------------------------------------------------------------
token_saving_vs_baseline_pct = (json_baseline_indexing_tokens -
format_indexing_tokens) / json_baseline_indexing_tokens * 100
  -> computed at the INDEXING stage only (it is null for json rows, the
  baseline itself).
  -> POSITIVE = format uses FEWER indexing tokens than JSON (a saving).
  -> NEGATIVE = format uses MORE indexing tokens than JSON (a cost).

  Worked example (bpolicy, fixed, 256):
    json indexing_tokens = 634,547  (baseline)
    toon indexing_tokens = 639,432  -> computed -0.77%  (column reports
    -0.77%)
    yaml indexing_tokens = 634,038  -> computed +0.08%  (column reports
    +0.08%)
    TOON is WORSE than JSON at indexing time; YAML is BETTER.

------------------------------------------------------------------------------
  format's own sum of squares, model spec held fixed, DV varied:

  core is a fully balanced/orthogonal design (3 format x 3 chunking x
  2 chunk_size x 2 generator x 4 corpus = 144, no empty cells), so under

  models, for both DVs.

  Consequence: the MODEL SPEC changes SIGNIFICANCE only by shrinking the
  residual - adding C(generator) [eta_sq~0.57] and C(corpus) [eta_sq~0.75]
  removes variance from the error term (residual SS: faithfulness 0.4839 ->
  0.0918), which inflates F for
  every remaining term including format, WITHOUT changing format's own
  effect. The DV changes the SIZE of the format effect itself: SS_format
  is 2.7x larger for faithfulness than for ragas_faithfulness, in
  both models - a real difference between the two constructs (5.5),
  independent of model spec.

  CONCLUSION: BOTH matter, for different, non-overlapping reasons.
    - Model spec is necessary for significance: even faithfulness's larger
      true effect is NOT significant under the two-way spec (F=1.3158,
      p=0.2717).
    - DV is necessary too: ragas_faithfulness stays non-significant even
      under the six-term spec (F=1.9060, p=0.1528) - the six-term model alone
      does not
      reproduce the original result on the RAGAS DV.
    - Only faithfulness UNDER the six-term spec reaches significance
      (F=6.6818, p=0.0017). Neither factor alone
      reproduces F(2,130)=6.68; both had to change together.

RESOLUTION: the pre-registered pooled two-way model finds no format
effect on ragas_faithfulness (F=0.4605, p=0.6319). The three-way and
per-corpus extensions show why: once corpus is modeled, format's effect
reverses direction by corpus, which no model ignoring corpus can resolve.

The frozen primary judge penalizes gpt-generated answers
by about 2.6 points more than it penalizes
claude-generated answers.

as evidence to discard the primary-judge results outright. ragas_faithfulness
is produced by a separate decompose-then-verify protocol and is not affected
by this judge.
